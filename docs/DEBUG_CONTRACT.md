# Shared debug controller (1.3.1 integration contract)

Load libchev.lua, Debug.lua, DebugWindow.lua, ReportWindow.lua, SelfTests.lua, then consumer code. `LibChev.NewDebugController(policy)` returns an addon-owned controller. The library owns logs/filtering/search/batching/test presentation/command dispatch/console creation and controls. Consumer adapters supply only private data and domain policies.

Owned policy fields:
- `addonName`, optional `title` (default addonName + ` Debug`).
- `getLog()` returns a private `{entries,chars,sequence,dropped}` store dynamically; `commitLog(store)` optionally synchronizes legacy consumer field aliases after mutations. Omit both to use an internal private store.
- `limits` is an AppendLog limits table; `clock()` optionally returns elapsed time.
- `getFilters()` returns category,search; `setFilters(category,search)` persists owned settings. Omit both for session-only filters.
- `getTests(reverse,present)` returns private cases; `testOptions(reverse,present)` optionally returns LibChev.RunTests options (QT supplies run=WithIsolatedState). The controller supplies reverse order and owns presentation. Optional `include(case)` selects cases appropriate for the requested environment; omitted cases are counted in `result.skipped`, not silently lost.
- `beforeTests()` optionally returns a token; `afterTests(token)` handles consumer-specific suite cleanup even after failures. No presentation/logging inside these hooks. For staggered execution these hooks span frames: they must not replace live stores, suppress production work, or leave fixtures installed. Put that isolation in each case's `setup`/`run`/`teardown`, which always complete together within one callback.
- `testOptions(...).schedule(callback)` opts **presented runs only** into staggered execution. It must enqueue the callback for a later frame (for example, the consumer's safe timer adapter); return false or throw to reject scheduling. Never invoke it inline. One selected case, including isolation and cleanup, runs per scheduled callback. Every individual case must also have bounded live-client cost; long simulations belong in the consumer's offline suite. No coroutine yield or timer occurs inside a test fixture.
- `getVersion()` and `getEnvironment()` return sanitized version and owned environment primitives for the standard shared header.
- `buildReport(...)` returns a bounded diagnostic string containing addon-specific state (no generic event history); library owns newest-history composition, total32768 character budget, and presentation.
- `print(text)` is chat fallback; `reload()` is an optional Reload UI adapter.
- `failureDetails` explicitly permits bounded sanitized failure details. Default false (required for PvPTogether); case names/summaries still shown.
- `ui={restricted,canMutate,createFrame,parent}` matches the existing report window ownership/restriction contract.
- `onWindow(frame)` optionally maintains a consumer alias after console creation. Never attach to a Blizzard frame.

Methods:
- `Append(text,category,elapsed)`, `Appendf(category,format,...)`, `AppendState(category,label,value)`, `ClearLog()`, `Clear()` (also reset filters), `RemoveCategory(category)`, `BeginBatch()`, `EndBatch()`.
- `GetCategory()`, `SetCategory(category)`, `GetSearch()`, `SetSearch(text)`, `GetCategories()`, `HasCategory(category)`.
- `EntryText(entry)`, `Matches(entry,category,search)`, `GetEntries(category,search)`, `GetText(category,search)`, `GetMetrics(category,search)` -> shown,chars,total. Omitted filters use current settings.
- `GetRecentText(maxChars)`, `BuildDiagnosticExport(...)`, `Refresh()`, `ShowLog()`, `ShowReport(text,title)`, `ShowDiagnostics(...)`, `IsShowingAll()`.
- `RunTests(reverse,present)` -> success,passed,failed,result. Default present=false is synchronous and headless, even if a scheduler is supplied, and does not mutate live log/UI. Without a scheduler, present=true also completes synchronously. An accepted staggered run returns `true,0,0,result` immediately with `result.status="running"`; the same owned result is updated until `status="complete"`, `"aborted"`, or `"cancelled"`. This initial true means accepted, not that tests passed. `completed` counts cases actually run, `total` counts selected cases plus any suite-level failures, and `skipped` counts excluded cases. A scheduling or suite-execution failure sets `status="aborted"` and `unrun` counts selected cases left unexecuted before framework failures are added. Check `status` and `failed` for final success. Initial progress, progress every 100 completed cases, and the final report share the same console. Presented runs replace TEST history, clear search, and select TEST unless a visible ALL log view is already open. Addon-specific test isolation remains consumer-owned.
- `CancelTests(reason)` cancels the active run, retains partial outcomes, calls suite cleanup once, and presents a final cancelled report. If called during a case, cleanup and final presentation wait for that case's isolation to unwind. Consumers should call this when disabling or destroying the controller. Scheduled callbacks from cancelled/completed runs and duplicate callback invocations are ignored. Cancellation does not interrupt a currently executing Lua case.
- `HandleCommand(command,...)` handles `test`, `runtests`, `debug`, `dump`, `dump clear`, `dump CATEGORY`, `diagnostics`, `diag`. Returns handled,success; callers dispatch domain commands separately. Pass optional domain report arguments to diagnostics.

Window/controller fields used by the shared view are owned: `window`, `mode` (log/report), `reportText`, `reportTitle`, `title`, `tailPinned`, `forceTail`. UI implementation is exclusively DebugWindow.lua: same controls, layout, category/search/tail/copy/test/diagnostic behavior for every consumer. Keep test-runner and fixtures headless by default. Consumer methods may be thin compatibility forwards; delete duplicate generic mechanics/UI.

`LibChev.FormatSafe(format,...)` and `LibChev.StateText(label,value)` expose the same safe primitive formatting for compatibility adapters; no foreign object coercion. Internal batches restore their previous depth after a failed policy callback. Presentation failures retain a chat test-summary fallback and never leave the runner locked.

The console keeps its native texture-only panel borders and tiled marble/rock artwork. Buttons use UIPanelButtonTemplate; its owned close control uses UIPanelCloseButtonNoScripts with guarded dismissal. SearchBoxTemplate supplies the native search icon, instructions and clear button. MinimalScrollBar supplies proportional thumb and arrow controls, mapping percentages onto the existing pixel-based scroll and tail-follow model. These templates instantiate private child regions. Inherited scripts retain native presentation and interaction under the consumer's restriction policy; held scrolling is cancelled after a denied update or release. The console does not use shared UI pools or register global frame names. Presented test runs end with one summary, including when bounded history evicts earlier details.

## Consumer translation

Pass `translate = function(sourceEnglishString) ... end` on the controller policy to localize shared controls, help/status text, report headings and test summaries. It is separate from `ui` and receives no self argument. Invalid translations fall back to English. Category/filter identifiers and raw diagnostic/test content retain their original values; only presentation strings are translated. See [LOCALIZATION.md](LOCALIZATION.md) for the English source keys and formatting rules.
